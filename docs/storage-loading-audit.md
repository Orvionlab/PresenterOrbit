# Storage and loading wait audit

Source review on 2026-11-14, after commit `89147df0`. This is an inventory of asynchronous dependencies and UI gates, not a timing benchmark. A busy flag proves that an operation waits for a result, not that it is slow on a particular machine. No live user workspace was opened or changed for this audit.

## Shared causes

- **Ordered workspace jobs.** `Lanes` has one serial worker per workspace. Mutations, authoring commits and operator commands that use this lane follow earlier jobs. Settings have a separate lane. This preserves revision and action ordering, but a small change or live action can wait behind a large save. Newer manual takes replace older queued takes; they do not skip workspace edits. See [state/lane.rs](../crates/orbit-app/src/state/lane.rs) and [automation/execute.rs](../crates/orbit-app/src/automation/execute.rs).
- **Canonical response after persistence.** Some controllers update their displayed state only after the host accepts and saves it. Others show a local draft immediately, but still disable interaction until the canonical response arrives. Background work therefore does not guarantee immediate interaction. See [state/runtime.rs](../crates/orbit-app/src/state/runtime.rs), [automation/save.rs](../crates/orbit-app/src/automation/save.rs) and [settings/persist.rs](../crates/orbit-app/src/settings/persist.rs).
- **Whole-workspace work for small edits.** `save_workspace_with_assets` reads the workspace; `save_read_workspace` clones it, validates collections, refreshes theme assignments and snapshots, stages a transaction, commits it, and reads the workspace again. Several semantic mutations also read the workspace before calling this save path. `read_workspace` assembles libraries, presentations, media, themes and configuration from their files. See [workspace.rs](../crates/orbit-host/src/workspace.rs).
- **Collection-level serialization.** Unchanged collections are skipped. However, changing the library collection calls `write_libraries`, which walks and serializes the presentations in its libraries, even for a small edit to one presentation. This is broader work than updating one slide. Transaction staging and committing are additional work; this does not mean every unchanged asset is copied or every unchanged final file is rewritten.
- **Conflict protection and recovery.** Some editors load a fresh snapshot before saving to detect edits to the same document. Revision conflicts can require a refresh and, where supported, a replay. These checks protect data; their full-workspace cost can be reduced without removing them.
- **UI adoption and rendering.** A response may still need snapshot parsing, rebuilding cue documents, rasterizing previews and publishing an output scene. Storage completion and visible completion are separate stages.

## Recommended order

1. Remove the remaining canvas interaction/navigation dependency on storage completion, retaining local drafts, ordered edits, undo history and explicit save failures. Preserve the immediate document-tab behavior already implemented.
2. Narrow media busy states to the item/operation being edited and remove unnecessary full snapshot round trips where typed partial responses suffice.
3. Add immediate local feedback to common settings changes with request/revision-aware reconciliation. Persist on the existing queues; do not let older acknowledgements overwrite newer choices.
4. Reduce the shared host save cost: avoid repeated reads of the same workspace, refresh only affected theme dependencies, and stage only affected presentation files. Preserve validation and transactional durability.
5. Measure queue wait, host validation/serialization, filesystem commit, response parsing and first visible update separately on a scratch copy of a large workspace. Use those measurements before changing operator-command ordering or introducing additional caches.

Local interaction can usually be immediate even though durable saving takes time. Confirming export/import completion, switching to data that has not loaded, external device effects and successful synchronization still requires a real result. Merely removing busy flags would allow stale writes and does not make storage faster.

## Implementation review

The inventory above records the original findings. The following changes address the waits found during the implementation pass; it is not a claim of measured end-to-end latency.

| Inventory area | Resolution |
| --- | --- |
| Canvas object editing and undo/redo | Ordinary commits now use a per-document queue. Edits and history update locally before persistence; later commits use the accepted base of the previous commit. Failed drafts remain available and errors are reported. |
| Ordinary canvas slide/document switching | Navigation no longer waits for an ordinary canvas commit. Returning to a pending document shows its latest queued edit. Structural document operations and queued presentation-level operations retain their ordering gate. |
| Theme/prop/mask/stage canvas | Uses the same ordinary commit queue. Editing another slide in the same presentation/theme preserves the other slide's changes. Conflicting changes to the edited slide or theme properties still fail explicitly. |
| Inspector automatic saving | The existing 700/350 ms debounce remains; it batches typing rather than delaying the local preview. |
| Presentation/Slide/Build and transition labels | Existing immediate document previews remain. Ordinary canvas saves drain before queued document operations so the two paths cannot overwrite each other. |
| Media/Graphics/Audio inspector | Extended the existing optimistic reorder mechanism to media and library settings. Asset properties, transport, effects, routing and marker fields remain editable during ordinary saves. Later edits are reconciled with host normalization before the next write. File import, deletion, thumbnail extraction and maintenance keep their operation guards. |
| Video inputs | Pending input definitions are shown locally. Draft controls remain editable, and an older save does not dismiss a subsequently edited draft. Saving/creating/deleting still confirms identity and dependencies through the host. |
| General/appearance/remote/audio settings | Added shared local settings drafts, including immediate appearance updates. Saves submit only changed settings fields over the latest host settings; pending newer choices stay visible over older responses. Audio device effects remain host-confirmed. |
| Existing screens, groups and key mappings | Added workspace-scoped previews using the host's existing pure validation helpers. Newer accepted screen revisions cannot be replaced by an older response. Creation/deletion and other structural operations still use host-confirmed identities and dependency checks. |
| Song metadata | Fields remain editable during a submitted save; completion closes only an unchanged form. A later edit remains available for the next save. |
| Macros/messages/calendar | These forms already allowed draft editing. Completion now respects newer edits instead of closing the newer draft; message save-and-show uses the submitted message identity. Duplicate commits and dependent live actions still wait for the accepted definition. |
| Props, timers, stage, clear groups, Looks, audio inputs, devices and trigger management | Reviewed: drafts/local controls already remain usable in the relevant editors; busy guards principally protect duplicate submissions, collection structure, or device/runtime actions. These guards remain. Shared host-save work is reduced below. |
| Reflow | Text previews use the same host text-remapping logic as persistence. Entering the slide editor no longer awaits the text save. Split/merge still waits for validation and the selected slide identity returned by the host. |
| Chord charts | Reuses the full workspace already returned by the presentation mutation; removed a redundant disk snapshot read. Adopts an authoring update without treating it as opening a workspace again. |
| Bible/Planning Center/ticker/import service writes | Adopting a save no longer resets the workspace load generation. Actual search, download, parsing, action generations and dependency confirmations remain asynchronous result dependencies. |
| Startup, workspace switching/management, transfer, sync, updates, device discovery, cleanup | Retained completion waits: the requested data, external effect or file operation must exist before success can be reported. These paths run outside the UI thread. No fabricated results or early success were introduced. |
| Previews, output and linked text | Retained actual rendering/decoding and the existing refresh intervals. Live indicators continue to describe accepted output state. Operator-command ordering was preserved. |
| Shared host save | Presentation and arrangement mutations reuse the workspace they already read. Unrelated section saves skip theme assignment refresh. When themes are unchanged, theme refresh skips unchanged presentations and clones only the theme lookup data instead of the full workspace. Transactional writes, validation, conflict checks and canonical readback remain. |

Regression coverage includes blocked-storage canvas editing/navigation/undo, queued media fields, queued video-input definitions, immediate settings and screen/shortcut previews, and entering the editor from Reflow while storage is blocked. This implementation was verified through the repository checks and temporary-workspace tests; no live user workspace or output hardware was used for manual verification.
