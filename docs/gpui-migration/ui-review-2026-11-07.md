- State clarity: scan actions are neutral; destructive actions retain Danger. ToggleSwitch no longer uses success green for generic enabled state. Settings and video-input error lines use warning; the device panel's mixed saved/error feedback uses muted text. Error-only states were source-reviewed, not exercised in screenshots.
- Primitives: existing GPUI PanelHeader, list_row, EmptyState, CheckboxField, ToggleSwitch, and buttons are reused. Compact ActionButton is demonstrated in the native showcase and documented in the design system.
- Tokens/density: footer spacing and Settings navigation use theme metrics. Specialist cue thumbnails, output frames, meters, display maps, and canvas geometry retain rendering dimensions. No decorative shadow, gradient, nested panel card, or added uppercase label was found in the inspected regions.
- Utility siblings: Timers already uses `timer.empty`, Macros `automation.macros.empty`, Messages `automation.messages.empty`, and Stage `stage.noScreens`, through EmptyState. They do not duplicate their create actions. This was checked in source, not by navigating their native windows.
- Access: sidebar file roots expose a button role, selected state, translated label, tab stop, and Enter/Space activation. A GPUI mouse-input test switches both roots and verifies no workspace write. Existing switch interaction tests cover the enlarged label hit area.
- Themes/access scope: final dark/Dutch at comfortable density was viewed. Light theme, other densities/text scales, on-air output/hardware, and other operating systems were not visually verified. Existing Settings tests draw all panels in both languages and the densest theme.
